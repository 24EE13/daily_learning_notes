# 委托

## 委托是什么
简单来说是函数的容器，本质上是一种特殊的类。

## 委托的声明  

*写在namespace或class中*   
```cs
public delegate int Func(int a); //默认是public的访问类型,delegate关键字，其他的跟函数无异
```

## 委托的使用

调用委托本质上是调用函数，往委托里塞入函数不会复制函数本身。

```cs
//初始化（实例化）
Func f = new Func(函数1，函数2...);//方法1
Func f = 方法名;//方法2
Func f;//方法3
//添加函数（委托可以有多个函数）
f += 方法;
//删除函数
f-=方法;
//清空委托
f = null;
//调用委托
f.Invoke();
f();

//如果是含参函数。。。（锟斤拷）
```

委托可以作为函数参数，将函数传入另一个函数

```cs
//带有委托的函数
void func(Func f){
    print("12345");
}
void func2(){
    print("21");
}

//使用
int main(){
    Func f = func2;
    func(f);
    func(func2);//可以直接传函数名；
    
    return 0;
}
```

## unity系统自带委托

Action
默认无参无返回值。
Func
有返回值

```cs
Action<int,float> a;//两个参数
Func<int,float> b;//最后一个是返回值 

```

# 事件
事件是委托的包装，本质是一种特殊变量类型。



事件的声明
```cs
event Action 事件名;

```

事件的定义与使用和委托差不多，但不同的是，事件只能在类或者结构体中调用或赋值（不包括添加+=和删除-=）。


# 匿名函数（基本被lambda代替了）

顾名思义就是没有名字的函数

```cs
//匿名函数不能抛开委托或事件单独执行
Action a = delegate(参数){
 //函数逻辑
};//不要忘了这个分号

a();

```

有参的情况：
```cs
Action<int> a = delegate(参数){
    //函数逻辑

};

a(1);

```

有返回值的情况
```cs
Func<int> b = delegate(){
    //函数逻辑
};

b();
```

## 匿名函数应用

1. 当作函数参数

```cs
int main(){
    func(delegate(){
        //函数逻辑
    });
}

void func(Action a){
    a();
}
```

2. 当作函数返回值

```cs
int main(){
    //三种调用方法
    func()();//第二个是匿名函数的参数
    
    Action a = func();
    a();

    func().Invoke();

}

Action func(){
    //
    return delegate(){
        //函数逻辑
    }
}
```

匿名函数由于没有名称，其无法在委托中单独删除。


# lambda表达式

可以理解为`匿名函数`的简写，写法不同但使用上与`匿名函数`几乎一摸一样。
一般都用这个。

```cs
Action  a = (参数列表) ->{
    //函数逻辑
};
```

```cs
//有参数
Action<int> a = (int b)->{
    //函数逻辑
}; 
Action<int> a1 = (b)->{//也可以省略参数类型
    //函数逻辑
}; 

//有返回值
Func<int> b = ()->{
    //函数逻辑
};
```
其他与匿名函数大差不差，故略。

# 闭包(难)

内层函数可以引用外层函数的变量
并且内层函数引用的外层函数变量相当于引用变量本身，这意味着变量取得是最后改变的值。


```cs
class Test{
    Action a;
    Action b;
    
    int value = 1;

    a = ()->{
        print(value);
    };//使用a时输出1

    for(int i = 0;i < 10;i++){
        b = ()->{
            print(i);
        };//使用b时输出10个10（而不是从0到9）！！！
    }
}

```

**!!这里要注意一点：闭包的变量改变了它们的生命周期，除非是释放委托，它们会一直占用空间。**
